# Rhea Stack Directive — v1.2

You are building inside the **Rhea** monorepo. **All apps** (`grubgauge/`, `clarity/`, `daily-anchor/`, future) share **this single directive** — align implementation with each app’s **`package.json`**; upgrade apps that lag when you touch them.

## Canonical stack *(verify pins in repo)*

| Layer | Canonical *(GrubGauge / Clarity)* | Notes |

| **Lint** | **ESLint 9** + **`eslint-config-next`** matching that app’s Next major | |
| **Deployment** | **Vercel** | |
| **UI** | Minimal, calm, high signal-to-noise; responsive by default | |

**State:** Prefer **React state** / **context** for small surfaces; **Zustand** only when complexity warrants it (not currently required in canonical apps — add dependency **with user approval**).

---

## Data / backend *(select per product; not one-size-for-all)*

- **localStorage-only** — valid for lightweight rituals (e.g. **Daily Anchor**, **Clarity** decisions).
- **Supabase** (or another explicit backend) — when the product needs sync, auth, or shared data (e.g. **GrubGauge**). Document env vars in Vercel and **`README`**.

**Constraint:** Prefer **deletion over addition**; no new dependency without **c = e s i²** and explicit approval for stack changes.

---

## When suggesting code

- Default to the **canonical** row above; for **`daily-anchor/`** read **`package.json`** first and avoid forcing Next 16 APIs until the app is upgraded.
- Only propose **major** stack changes after **user approval** and justification through **c = e s i²**.
- Favor smaller bundles, faster loads, fewer abstractions.
